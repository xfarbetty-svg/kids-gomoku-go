## Context

請參見 `proposal.md`。目前 `learn.html` 雖然已建立 4 階段階梯影子跟讀訓練法（磨耳朵、精讀、視讀跟讀、脫稿影子跟讀）與 Web Speech API 語音處理管線，但資料層嚴重失衡，影子跟讀僅有英語故事，日語篇章為空或缺失，且整體生活情境對話與單字例句過於簡略。

## Goals / Non-Goals

**Goals:**
- **日語影子教材系統化**：在 `SHADOWING_DATA.ja` 建立分級篇章庫（初級日常對話、中級童話民間故事、高級實用短講演說），每句具備日語漢字、假名標註（Furigana）與繁體中文。
- **HTML5 `<ruby>` 原生標音渲染**：在介面上以標準 HTML `<ruby>` 與 `<rt>` 呈現日語漢字標音，確保手機與桌面端排版清晰。
- **日語語音辨識與比對最佳化**：支援 Web Speech `ja-JP`，透過日文字元正規化與 Levenshtein 編輯距離演算法計算語音辨識相似度，產出客觀星星評分。
- **英語跟讀篇章與生活語料充實**：擴充英語分級篇章、深化情境對話劇本（涵蓋 12 大生活場景），並擴增分級生活例句。
- **維持純前端 PWA 特性**：完全不依賴外部後端伺服器，所有語料庫均可離線快取於瀏覽器。

**Non-Goals:**
- 不串接昂貴的第三方付費雲端語音 API（如 Google Cloud Speech 或 Azure），保持專案輕量與零成本維護。
- 不更動既有的 4 階跟讀核心狀態機架構（維持磨耳朵、精讀、視讀、脫稿影子），專注於語料擴充與多語系深化。

## Decisions

### 1. 日語教材結構與 `<ruby>` 標音
- **決策**：在句子資料中儲存包含漢字與平假名的結構，或提供預先排版好的日文標音句子，介面採用 `<ruby>漢字<rt>かんじ</rt></ruby>` 語意標籤。
- **替代方案**：使用第三方純前端分詞庫（如 Kuromoji.js）即時標音。
- **考量**：Kuromoji 字典檔高達 10MB+，會拖慢手機載入速度且增加複雜度；採用高品質預編譯教材資料更為輕巧可靠。

### 2. 日語口說辨識正規化
- **決策**：日語比對時，去除標點符號與多餘空格，並將全形/半形字符標準化後，執行字元級動態規劃編輯距離（Levenshtein Distance）比對。

### 3. 教材資料結構擴充
- **決策**：擴充 `SHADOWING_DATA`，日英雙語皆具備完整的 `beginner`、`intermediate`、`advanced` 多篇精選長文分句。

## Risks / Trade-offs

- **[風險]** 部分手機瀏覽器對日語 `ja-JP` 語音辨識支援度不一（如特定 Android 瀏覽器可能無日語離線辨識包）。
  - **緩解措施**：保留「安靜送出 / 手動打卡」以及「聽原音示範」機制，即便使用者當下無法用語音辨識，依然能流暢完成 4 階梯跟讀練習。
- **[風險]** 擴充多篇教材後 JS 體積稍微增加。
  - **緩解措施**：教材採結構化乾淨物件，體積增長僅數十 KB，Service Worker 快取後對載入速度毫無影響。
